# Безопасность и данные

## Доступ к данным

Данные пользователя изолируются по аккаунту. Один пользователь не должен видеть проекты, чаты, файлы и платежные данные другого пользователя.

## Аккаунт

Основной публичный сценарий входа:

- email;
- пароль;
- регистрация с принятием условий;
- восстановление пароля через письмо после подключения SMTP.

Временная синхронизация по коду не должна быть основным способом авторизации для клиентов.

## Платежи

Платежи проходят через YooKassa. Платформа не хранит данные банковских карт.

Перед продажами нужно пройти test payment и webhook smoke:

- создание платежа;
- успешный callback;
- идемпотентная обработка webhook;
- начисление подписки, токенов и расширенного storage;
- корректная отмена или отказ платежа.

## Файлы

AI-редактирование файлов выполняется только через preview/diff и approve. Модель не должна молча менять файлы без подтверждения пользователя.

## Production-правила

- секреты не хранятся в git;
- production использует PostgreSQL;
- миграции применяются через Alembic;
- runtime-файлы и базы не коммитятся;
- SMTP, YooKassa и AI-провайдеры должны быть отражены в readiness endpoint;
- перед продажами проходят smoke-тесты auth, billing, лимитов, storage accounting и browser QA.
