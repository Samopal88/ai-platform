# AGENT_INTERACTION_SPEC
## AI Workspace Platform

---

# 1. Назначение документа

Документ описывает, как взаимодействуют между собой:

- пользователь
- GPT-5.4 как оркестратор
- Claude Code как исполнитель
- backend платформы
- инструменты (tools)

Цель: обеспечить управляемую, поэтапную и контролируемую разработку платформы без хаотичного кода и без бесконтрольных действий агентов.

---

# 2. Роли участников

## 2.1 Пользователь

Пользователь выполняет роль:

- визионера проекта
- тестировщика
- утверждающего решения

Пользователь может:

- ставить цели
- утверждать или отклонять результат
- просить переделать
- останавливать задачу
- запускать следующий этап

---

## 2.2 GPT-5.4

GPT-5.4 выполняет роль:

- архитектора
- product manager
- tech lead
- оркестратора задач
- контролёра качества

GPT-5.4 отвечает за:

- понимание задачи пользователя
- выбор стратегии решения
- разбиение на подзадачи
- постановку задач Claude Code
- проверку результата Claude
- контроль соответствия техпроекту
- ведение памяти проекта
- принятие решения: продолжать / остановить / запросить approve

GPT-5.4 не должен без необходимости писать код сам.

---

## 2.3 Claude Code

Claude Code выполняет роль:

- разработчика
- исследователя кода
- редактора файлов
- исполнителя узких подзадач

Claude Code отвечает за:

- чтение проекта
- изменение файлов
- запуск команд
- создание артефактов
- подготовку diff
- исправление ошибок
- выполнение точечных задач

Claude Code не принимает архитектурных решений самостоятельно.

---

# 3. Основной принцип взаимодействия

Пользователь общается только с GPT-5.4.

GPT-5.4:

1. получает запрос пользователя
2. анализирует контекст
3. решает, нужен ли Claude Code
4. формирует узкую подзадачу
5. передаёт её Claude Code
6. получает результат
7. проверяет результат
8. показывает пользователю статус и итог
9. запрашивает approve, если требуется

---

# 4. Правило поэтапной работы

Запрещено передавать Claude Code слишком широкие задачи.

Плохо:

> Сделай всю платформу.

Хорошо:

> Создай SQLAlchemy модели для users, projects, chats, messages и подготовь миграцию.

Каждая подзадача должна быть:

- ограниченной
- проверяемой
- измеримой
- дающей артефакт результата

---

# 5. Режимы задач для Claude Code

GPT-5.4 может запускать Claude Code в одном из режимов.

## 5.1 INVESTIGATE

Claude только исследует.

Разрешено:

- читать файлы
- анализировать код
- запускать безопасные команды
- возвращать вывод

Запрещено:

- менять файлы
- делать commit
- менять конфиги
- запускать деплой

---

## 5.2 PLAN

Claude предлагает план изменений.

Разрешено:

- анализировать структуру
- описывать шаги
- перечислять нужные файлы
- указывать риски

Запрещено:

- менять файлы

---

## 5.3 PATCH

Claude меняет файлы в рамках поставленной задачи.

Разрешено:

- редактировать файлы
- создавать файлы
- запускать локальные проверки

Требуется:

- diff
- список изменённых файлов
- краткий отчёт

---

## 5.4 VERIFY

Claude проверяет, что сделанное изменение работает.

Разрешено:

- запускать тесты
- запускать linters
- выполнять безопасные команды проверки
- возвращать лог

---

# 6. Шаблон постановки задачи Claude Code

Каждая задача Claude должна содержать:

- режим
- проект
- цель
- ограничения
- ожидаемый результат
- что запрещено
- формат ответа

Стандартный шаблон:

```text
Режим: {MODE}
Проект: {PROJECT_PATH}

Цель:
{TASK_DESCRIPTION}

Ограничения:
- Не выходить за рамки задачи
- Не делать широких рефакторингов
- Не изменять .env
- Не выполнять деплой
- Не менять секреты
- Не делать git push
- Не удалять файлы без прямого указания

Нужно вернуть:
1. Что сделано
2. Какие файлы затронуты
3. Какие команды запускались
4. Какие проблемы найдены
5. Следующий рекомендуемый шаг
```

---

# 7. Что GPT-5.4 обязан делать перед запуском Claude

Перед каждой задачей GPT-5.4 обязан:

1. проверить, есть ли уже нужная информация в памяти проекта
2. проверить, есть ли релевантные файлы в индексе
3. понять, действительно ли нужен Claude
4. определить режим задачи
5. сформулировать задачу узко и проверяемо

---

# 8. Что GPT-5.4 обязан делать после ответа Claude

После каждого ответа Claude GPT-5.4 обязан:

1. проверить, соответствует ли ответ задаче
2. проверить, не вышел ли Claude за рамки
3. проверить, есть ли конкретный результат
4. проверить, есть ли подтверждение вывода логами/файлами
5. решить:
   - принять результат
   - отправить на доработку
   - запросить approve у пользователя
   - остановить выполнение

---

# 9. Approve / Reject логика

Пользователь должен утверждать:

- крупные блоки функциональности
- опасные изменения
- переход к следующему крупному этапу
- изменения архитектуры
- изменения конфигов
- миграции
- действия, затрагивающие прод

Статусы:

- approve
- reject
- needs revision
- continue

---

# 10. Когда обязательно нужен approve

Approve обязателен, если Claude или GPT хотят:

- изменить архитектуру
- выполнить миграцию БД
- поменять конфигурацию
- редактировать секреты
- удалить файлы
- выполнять deploy/restart
- делать push в git
- перейти к следующему крупному этапу MVP

---

# 11. Что запрещено Claude Code без отдельного разрешения

Claude Code не может самостоятельно:

- выполнять deploy
- редактировать .env
- изменять секреты
- удалять каталоги
- делать git push
- менять системные пакеты
- устанавливать произвольный софт
- останавливать системные сервисы
- выполнять destructive commands

---

# 12. Что может делать Claude Code без approve

Claude может:

- читать файлы проекта
- создавать новые файлы в проекте
- редактировать код в рамках подзадачи
- запускать тесты
- запускать линтеры
- выполнять безопасные команды анализа
- формировать diff и отчёт

---

# 13. Формат ответа Claude Code

Claude обязан возвращать структурированный результат:

- summary
- changed_files
- commands_run
- warnings
- next_step
- diff_preview
- status

Пример:

```json
{
  "summary": "Созданы модели users, projects, chats, messages.",
  "changed_files": ["app/models.py", "alembic/versions/001_init.py"],
  "commands_run": ["pytest", "alembic revision --autogenerate"],
  "warnings": [],
  "next_step": "Создать CRUD endpoints для проектов.",
  "status": "completed"
}
```

---

# 14. Формат ответа GPT пользователю

GPT-5.4 отвечает пользователю в понятной форме:

- текущий этап
- что сделано
- что проверено
- что требует решения
- что предлагается дальше

Пример:

- Этап: Модели базы данных
- Сделано: созданы users, projects, chats, messages
- Проверка: миграция собрана, ошибок импорта нет
- Нужен approve: перейти к созданию API для проектов

---

# 15. Логирование

Система хранит:

- исходный запрос пользователя
- задачу GPT для Claude
- ответ Claude
- статус шага
- логи команд
- diff
- решение пользователя

Это нужно для:

- прозрачности
- отката
- аудита
- восстановления контекста

---

# 16. Правило "не уходить в бездумный код"

GPT-5.4 обязан останавливать Claude, если Claude:

- начинает менять лишние файлы
- предлагает переписать всё заново
- делает рефакторинг вне scope
- не может доказать проблему
- повторяет неудачные действия без новой гипотезы
- выходит за рамки утверждённого этапа

В таких случаях GPT должен:

- остановить задачу
- объяснить проблему
- предложить более узкий следующий шаг

---

# 17. Работа по техпроекту

GPT-5.4 обязан использовать как источник истины:

- VISION_DOCUMENT.md
- SYSTEM_ARCHITECTURE.md
- AGENT_INTERACTION_SPEC.md
- последующие проектные документы

Если Claude предлагает решение, противоречащее документам, GPT обязан отклонить его или вынести на approve пользователя.

---

# 18. Работа с этапами MVP

Разработка идёт этапами.

Пример:

1. Skeleton backend
2. Database models
3. Project/chat API
4. File storage
5. File indexing
6. Model routing via OpenCode
7. Claude task runner
8. Basic frontend
9. Voice input
10. Image generation
11. Web search
12. Final QA

Переход к следующему этапу — только после завершения текущего и, при необходимости, approve пользователя.

---

# 19. Поведение при ошибках

Если Claude вернул ошибку, GPT должен:

1. определить тип ошибки
2. понять, можно ли исправить её локально
3. не запускать бесконечные повторные попытки
4. при 2–3 неудачных попытках остановиться
5. объяснить пользователю, в чём проблема
6. предложить следующий шаг

---

# 20. Итоговый принцип

Система должна работать как управляемая AI-команда:

- пользователь задаёт направление
- GPT-5.4 управляет процессом
- Claude Code выполняет узкие инженерные задачи
- каждый шаг прозрачен
- каждый крупный блок согласуется
- хаотичная генерация кода запрещена
